An open-source podcast transcript skill for your AI assistant · MIT

Turn an episode into a transcript worth reading.

No commands to learn. Ask your AI assistant in one sentence: it transcribes on your machine, then adds punctuation, speakers, and verified names—without cutting or summarizing—and hands you Markdown and HTML.

1Install — send this to your AI assistant
Install this skill for me: https://github.com/ZHUCH-520/podcast-transcript-public/tree/main/podcast-transcript-public
2Use — hand it an episode
Use podcast-transcript-public to turn this episode into a clean English transcript: <episode link>

Codex installs it with its built-in skill-installer, ready on your next message. Claude Code, Cursor and others have no built-in installer—your assistant copies the folder into its skills directory with a command and asks before running it; if the skill doesn't show up, start a new session. Before the first audio job, it tells you what it needs to download, how big it is, and where it goes—nothing starts until you say yes.

No AI assistant? Use the command line (needs Python 3.9+ and FFmpeg)
pipx install "git+https://github.com/ZHUCH-520/podcast-transcript-public.git" podcast-transcript run episode.mp3 --output-dir ./episode --accept-download --language en

The CLI gives you a raw transcript (barely punctuated) and optional captions; the readable, proofread version comes from the AI-assistant step. To install into TRAE, Lingma, Kimi Code and others: podcast-transcript install-skill --target <tool> (--list shows them all).

What happens next

Send the source.
It handles the rest in six steps.

Every step stays auditable. The original audio and rough transcript remain available, and uncertain names are marked instead of invented.

01 / INPUT

Identify the source

Use an episode link, audio, video, or an existing transcript. Say whether you want English, Chinese, or both.

02 / PRESERVE

Keep the originals

Each episode gets its own folder. Source media and rough transcripts remain available for later checks.

03 / TRANSCRIBE

Turn speech into text

The skill checks your computer and shows the runtime, model, download size, storage location, and network activity before setting anything up.

04 / VERIFY

Check names, split safely

Guest names and terminology are checked against the episode page. Long transcripts are split losslessly with the bundled script.

05 / EDIT

Your assistant proofreads each chunk

Your AI assistant fixes punctuation, speaker labels, and obvious recognition errors without cutting substance. This step sends the transcript text to that assistant's model.

06 / EXPORT

Merge, check, export

The beginning, ending, gaps, duplicates, and formatting are checked before creating transcript.md and transcript.html.

What it protects

Readable, without sanding off
the speaker's voice.

Spoken language can be tidied up. The point and the tone stay. Anything uncertain goes into Unresolved Items for you to review.

01 · COMPLETE

Nothing important goes missing

Claims, examples, and caveats stay in. A summary may help you enter the piece, but it never replaces the full transcript.

02 · GROUNDED

Names aren't guessed

Names are checked when a reliable source exists. Otherwise the transcript uses a neutral label for your review.

03 · HUMAN

The voice still sounds familiar

Useful pauses, humor, and speaking habits remain. Only obvious recognition noise is removed.

04 · PORTABLE

The files are ready to use

You get transcript.md for editing and transcript.html for reading or sharing, plus Unresolved Items only when something needs checking.

Then choose what to download.

The skill checks your machine before choosing a transcription path. It shows the model, size, storage location, and network work clearly, then waits for your approval.

Before you start: an AI coding assistant that loads skills (Codex, Claude Code, Cursor, and others), Python 3.9+, and FFmpeg. The tool never installs system software for you. Speaker diarization also needs a Hugging Face account: accept the pyannote model terms, then set HF_TOKEN (or HUGGING_FACE_HUB_TOKEN).

small

about 480 MB

Start quickly. The fastest option for a first episode or modest hardware, though names, accents, and noisy recordings may need more correction.

turbo

about 3.2 GB on Apple Silicon, about 1.6 GB on Windows and Linux

Balanced. The usual recommendation for newer Apple Silicon Macs, and a good fit for Windows or Linux with a suitable GPU.

large-v3

about 3.2 GB

Accuracy first. Better suited to name-heavy shows, strong accents, or uneven recordings. It uses more time and memory, and is never chosen automatically.

Sizes are the pinned downloads in the repo, rounded. Apple Silicon Mac uses MLX Whisper; Intel Mac, Windows, and Linux use faster-whisper.

Already have a rough transcript? Skip Whisper and the model download—send the text as it is.

Where your files go

Audio stays local.
Text goes only to the AI you choose.

Audio and transcription run on your machine. Proofreading sends the transcript text to the AI assistant you're using (for example Codex or Claude Code), under that provider's data policy. Network use for fetching episodes or checking names is announced first; cloud transcription of audio needs your explicit approval.

Paywalls, sign-ins, DRM, and platform protections are not bypassed. If access is restricted, provide media or text you obtained legally.

FAQ

A few things worth knowing
before you install.

Model choice, file storage, speaker names, and protected media—answered plainly.

Will my audio be uploaded?

Your audio, no. Transcription runs locally. The transcript text is sent to your AI assistant's model for proofreading. Cloud transcription only happens after you approve the service and the data it needs.

Which AI assistants work?

Codex installs from one sentence and can use the skill on your next message. Claude Code and Cursor have no built-in installer: the assistant copies the folder into its skills directory after you approve, or you can run podcast-transcript install-skill --target claude or cursor. TRAE, Lingma, Qoder, CodeBuddy, Qwen Code, and Kimi Code install with install-skill into directories whose locations were checked. Other hosts that read SKILL.md usually work too. Those locations were checked from the docs, not live-tested inside every product.

Does it cost money?

The tool is free and MIT-licensed. Local transcription costs nothing. Proofreading uses your AI assistant's own quota.

Can it handle Chinese and English together?

Yes. Use zh-en. English names are more likely to stay in Latin script, and you can put names in a glossary file.

Does small reduce transcription quality?

Sometimes, especially with names, strong accents, or background noise. The tradeoff is a roughly 480 MB download and a faster run. Start there for a trial, then move to turbo or large-v3 if the recording needs more accuracy.

Where are models stored?

In your operating system's user cache—not inside the episode folder or skill folder. The exact location is shown before download.

I already have a rough transcript. Do I need a model?

No. The skill keeps the rough text, splits it into small chunks, and goes straight to checking and editing.

Will it identify every speaker?

Not reliably in every recording. Optional local diarization can add IDs such as SPEAKER_00, but those IDs are not names. The first pyannote download needs you to accept the model terms on Hugging Face and set HF_TOKEN (or HUGGING_FACE_HUB_TOKEN). When names can be verified, they are used. Otherwise the transcript keeps a neutral label such as Speaker A for you to review.

Will it bypass a paywall or protected media?

No. It stops at sign-ins, payment gates, DRM, and platform protection, then asks you for media or text you have the right to use.

Does it publish the transcript when finished?

No. It creates local Markdown and HTML files, then stops. Publishing is your decision.
