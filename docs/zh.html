装进 AI 助手的播客转写 skill · MIT 开源

一集播客，变成一份好读的文字稿。

不用学命令。跟你的 AI 助手说一句话，它就会在你电脑上转写，再补标点、分说话人、核对人名，不删内容、不缩成摘要，最后给你 Markdown 和 HTML。

1安装：把这句话发给你的 AI 助手
帮我安装这个 skill：https://github.com/ZHUCH-520/podcast-transcript-public/tree/main/podcast-transcript-public
2使用：发一期节目给它
请用 podcast-transcript-public 帮我把这期播客整理成中文文字稿：<小宇宙 / Apple Podcasts 链接>

Codex 会用自带的 skill-installer 装好，下一条消息就能用。Claude Code、Cursor 等没有内置安装器，助手会用命令把文件夹复制到它的 skill 目录，执行前会问你；装好后如果没出现，新开一个会话。第一次处理音频前，会先告诉你要下载什么、多大、存在哪，你同意才开始。

不用 AI 助手，只要命令行（需要 Python 3.9+ 和 FFmpeg）
pipx install "git+https://github.com/ZHUCH-520/podcast-transcript-public.git" podcast-transcript run episode.mp3 --output-dir ./episode --accept-download --language zh-en

命令行只出粗转录（几乎没有标点）和可选字幕，好读的精校稿要靠 AI 助手那一步。装进 TRAE、通义灵码、Kimi Code 等：podcast-transcript install-skill --target <工具名>（--list 查看全部）。

它会怎么做

交给它之后，分六步完成。

每一步都能回头核对。原始音频和粗转录会留着，名字查不到也不会硬猜。

01 / 收材料

先确认材料

链接、音频、视频或现成转录都可以。你只要说明要中文、英文还是双语。

02 / 存原稿

单独保存这一期

每期用一个文件夹，原始音频和粗转录留着，方便回头核对。

03 / 转文字

转成文字

先检查电脑，告诉你用哪个模型、要下多大、存在哪、哪些步骤要联网。你同意后才下载，转写在本机完成。

04 / 查名字

查人名，切长稿

对照节目页核对嘉宾名和术语；长稿用自带脚本切成小段，一个字不丢。

05 / 整理

交给 AI 助手逐段校对

你的 AI 助手逐段补标点、分说话人、修明显错字，观点一句不删。这一步会把文字稿发给该助手使用的模型。

06 / 导出

合并后再检查

检查开头结尾、重复、漏段和格式，生成 transcript.md 和 transcript.html。

它最在意什么

那个人在说话。

口头表达可以整理，观点和语气要留下。拿不准的地方会标出来，交给你确认。

01 · 不缺段

不漏内容

观点、例子和限定条件都要留下。摘要可以有，但不能顶替逐字稿。

02 · 不乱猜

人名不乱猜

能查到就核对，查不到就用中性标签，留给你确认。

03 · 像本人

保留说话方式

有用的停顿、幽默和口头习惯会保留，只清理明显的转写噪音。

04 · 能直接用

文件拿来就能用

transcript.md 方便改，transcript.html 方便读和分享；有拿不准的地方，会单列“待确认”清单。

第一次处理音视频

先看准备方案，
再决定下不下载。

它会先检查电脑，看看适合哪种转写方式。模型、大小和保存位置都会列清楚，得到你的同意才开始。

需要先准备：一个支持 skill 的 AI 编程助手（Codex、Claude Code、Cursor 等）；Python 3.9+；FFmpeg（工具不会替你安装系统软件）。想自动区分说话人，还需要一个 Hugging Face 账号：先在 pyannote 模型页同意使用条款，再设置 HF_TOKEN（或 HUGGING_FACE_HUB_TOKEN）。

small

约 480 MB

先跑起来。适合先试一集，或配置普通的电脑。人名、口音和嘈杂录音可能要多改几处。

turbo

Apple Silicon 约 3.2 GB，Windows / Linux 约 1.6 GB

比较均衡。新一些的 Apple Silicon Mac 会优先推荐这一档；合适的 Windows 或 Linux 显卡也可以用。

large-v3

约 3.2 GB

更看重效果。适合人名多、口音重或录音质量一般的内容，也更吃时间和内存。不会被自动选中。

体积是仓库里钉死的模型大小，四舍五入。Apple Silicon Mac 使用 MLX Whisper；Intel Mac、Windows 和 Linux 使用 faster-whisper。

已经有粗转录？直接交给它就行，不用安装 Whisper，也不用下载模型。

你的文件会去哪

音频不出本机，文字稿交给你选的 AI。

音频和转写都在你的电脑上完成。校对这一步会把文字稿交给你正在用的 AI 助手（比如 Codex、Claude Code），由它背后的模型处理，适用该服务自己的数据政策。下载节目、核对人名要联网时会先说明；音频要交给云端转写，必须你明确同意。

付费墙、登录、DRM 或平台保护不会被绕过。遇到这些情况，你可以提供自己合法取得的音频或文稿。

01

音频默认不上传

转写在本机完成。云端转写需要你明确同意。

02

文字稿会交给 AI 校对

只发文字，不发音频；发给哪个模型，取决于你用的助手。敏感内容可以只跑命令行，拿粗转录自己看。

03

网页不会跟踪你

页面没有分析脚本、追踪像素、外部字体或其他外部资源。

04

下载前先给你看

模型档位、大小和保存位置会先列出来。没有同意，不会开始下载。

05

生成后由你决定去哪

Markdown 和 HTML 生成后就停下。要不要上传由你决定。

常见问题

装之前，
可能还想问这些。

模型怎么选、文件放哪里、认不认得说话人，都放在这里。

音频会被上传吗？

音频不会。转写在本机完成。但校对时，文字稿会发给你用的 AI 助手的模型。需要云端转写时，会先说明服务和要发送的数据，你同意才发。

支持哪些 AI 助手？

Codex 说一句话就能装，下一条消息可用。Claude Code 和 Cursor 没有内置安装器，助手会在你确认后把文件夹复制到它的 skill 目录；也可以先装好命令行，再运行 podcast-transcript install-skill --target claude 或 cursor。TRAE、通义灵码、Qoder、CodeBuddy、Qwen Code、Kimi Code 用 install-skill 复制到已经核对过的目录。其他能读取 SKILL.md 的工具通常也能用。名单是核对过安装位置，不是每个产品都做过实机验收。

要花钱吗？

工具本身 MIT 开源、免费。转写在本机跑，不花钱。校对消耗的是你 AI 助手自己的额度。

中英混说行吗？

行。用 zh-en 模式，英文专名尽量保留原样；人名可以放进 glossary 文件。

small 会不会影响转写效果？

会有一些影响，尤其是人名、口音重或背景声多的时候。它的好处是下载大约 480 MB、速度更快，适合先试一集；需要更稳时可以选 turbo 或 large-v3。

模型保存在哪里？

放在系统的用户缓存目录，不会放进节目文件夹或 skill 文件夹。下载前会显示具体位置。

我已经有粗转录，还要下载模型吗？

不用。它会保留粗稿，切成小段后直接校对和整理。

它总能认出所有说话人吗？

不能保证。可以选择安装本地说话人分离，它只会给出 SPEAKER_00 这样的编号，不是真实姓名。第一次下载 pyannote 模型时，需要在 Hugging Face 同意使用条款，并设置 HF_TOKEN（或 HUGGING_FACE_HUB_TOKEN）。节目页能确认名字时就写名字，确认不了就用 Speaker A 或说话人 A，留给你复核。

它会绕过付费墙或受保护媒体吗？

不会。遇到登录、付费、DRM 或平台保护时，它会停下来，请你提供合法取得的音频或文稿。

完成后会自动发布吗？

不会。它只生成本地 Markdown 和 HTML。是否上传，由你决定。
